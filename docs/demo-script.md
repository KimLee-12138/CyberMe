# CyberMe RAG Demo 脚本（6 分钟）

> 目标：用 6 分钟证明“你的课程资料能被检索、回答、引用、拒答”。
> 不演示：同步、写回、pgvector、Celery、完整知识图谱（这些还没做/不是本轮重点）。

---

## 0. 演示前 5 分钟检查

1. 后端已启动：
   ```powershell
   cd D:\CyberMe\repo\apps\api
   $env:DEEPSEEK_API_KEY=[Environment]::GetEnvironmentVariable('DEEPSEEK_API_KEY','User')
   python -m uvicorn app.main:app --host 127.0.0.1 --port 8002
   ```
2. 前端已启动：
   ```powershell
   cd D:\CyberMe\repo\apps\web
   npm run dev
   ```
3. 浏览器打开 `http://localhost:3000/ask`，已登录。
4. **预热一次**：先问一个简单问题（如“什么是函数依赖？”），让索引加载、DeepSeek 连接热起来；然后点“清空对话”。
5. 确认页面顶部显示 `RAG v1 · 5,187 chunks · 2,632 notes`。
6. 关闭无关标签页，准备好 `data/README.md` 或 `data/manifest_v1.json` 作为数据页。

## 1. 开场（30 秒）

> “这是我们课程资料的 RAG 纵切：868 个原始 PDF/Markdown，筛出 410 个可用文件，蒸馏成 433 篇笔记、4,523 个知识单元。现在问一个问题，系统只从这些资料里找证据，找不到就拒答。”

## 2. 数据质量看板（1 分钟）

打开 `http://localhost:3000/quality`，按顺序指：

1. **顶部 KPI**：868 原始 → 410 纳入 → 309 蒸馏 → 4,523 单元 → 433 笔记。
2. **语料漏斗**：文件级 → 内容级 → 知识级；section part 和 unit 会放大，不能按文件数直接比较。
3. **质量分级**：150 官方 / 233 待复核 / 10 候选 / 15 重复 / 2 隔离；383 可索引、309 蒸馏、48 篇抽查。
4. **排除原因**：内容过短 223、课程范围外 163、完全重复 134、扫描无文本 129、项目/代码 127。
5. **按课程分布**：20 门有内容课程；Tab 切「冲突 4 / 隔离 2 / 公式缺失 73 / 近重复 203 / 写回 433」。

补一句：

> “不是把 868 个文件直接塞给模型，而是先做哈希对齐、去重、质量评分、分节，再蒸馏；每个笔记都能回到来源文件和页码。隔离和冲突不藏起来，直接放在看板上。”

## 3. 问答演示（2 分钟）

### 3.1 定义题

选择课程「数据库」，问：

> **什么是函数依赖？**

预期：

- 回答给出定义、平凡/非平凡、完全/部分依赖；
- 引用 chips `[E1]–[E5]`；
- 右侧证据面板显示 `DB-TOPIC-006 §定义`、`§易错点`，页码 `p.1–2`。

讲解点：

> “答案不是模型自由发挥，而是从 433 篇笔记里检索出证据，再让模型带 `[E1]` 引用。”

### 3.2 比较题

问：

> **2NF 和 3NF 的区别是什么？**

预期：

- 回答：2NF 完全函数依赖 vs 3NF 消除传递依赖；
- 引用 `[E1][E2][E6]`；
- 右侧证据含 `DB-TOPIC-016 §易错点`、`DB-TOPIC-006 §易错点`。

讲解点：

> “比较题需要两个证据源；系统会同时检索笔记和原始 section。”

### 3.3 算法/公式题

课程切「算法」，问：

> **0/1 背包为什么容量要逆序？**

预期：

- 回答：防止同一物品被重复选取；
- 引用 `[E2]` 等；
- 公式区可能带“原文公式缺失”警告。

讲解点：

> “公式缺失时系统会明确提示，不会用模型知识补写。”

### 3.4 数据结构题

课程切「数据结构」，问：

> **栈和队列的区别是什么？**

预期：

- 回答 LIFO vs FIFO、插入/删除位置；
- 引用 `[E1][E5]`。

## 4. 拒答演示（1 分钟）

课程切「数据库」，问：

> **数据库索引的原理是什么？**

预期：

- 黄色「证据不足」；
- 回答明确说“现有证据只提到索引是数据库对象，没有说明内部原理”；
- 右侧仍显示检索到的 8 条证据，但 `citations=0`。

再问：

> **量子纠缠在数据库中的应用**

预期：

- 直接拒答：“没有找到足够依据”；
- 不编造量子计算内容。

讲解点：

> “这是系统最重要的能力之一：知道自己什么时候没有答案。”

## 5. 架构与限制（1 分钟）

画/说这条链：

```text
Vault / data
  → 868 → 410 → 309 → 414 part → 4,523 unit → 433 note
  → BM25 检索（5,187 chunks）
  → top 8 证据
  → DeepSeek Flash 生成
  → 引用 + 拒答
  → React ChatPage 证据面板
```

强调：

- 检索不依赖 Postgres/pgvector，启动加载预构建索引，演示稳定；
- 433 篇笔记、414 个 section 都可回溯到来源页码；
- 目前是 section 级引用，不是逐句精确页；
- 73 篇公式缺失已标记，没补写；
- 还没做：知识图谱页面、数据质量看板、4 切块 × 5 检索实验。

## 7. 答辩 Q&A 备用话术

**Q：数据怎么来的？**
> 868 个 PDF/MD → 哈希对齐 → 去扫描/乱码/重复/项目 → 410 个 → 309 个进入蒸馏 → 414 个 section part → 4,523 个知识单元 → 433 篇笔记。

**Q：chunk 怎么分？**
> 笔记按 H2 标题切（定义/关键点/公式/易错点），来源 section 按段落切 800 字符；检索块 5,187 个。

**Q：为什么用 BM25，不用向量？**
> 这是第一阶段基线；下一步加本地 `bge-small-zh` + RRF + rerank，做对比实验。DeepSeek 没有 embeddings API，所以向量用本地模型。

**Q：知识图谱呢？**
> 433 个主题、387 个 section、20 门课程、410 个来源已经具备建图条件；下一步做 Course→Section→Topic→Source 的确定性图，再加 AI 候选前置/对比边。本轮先把 RAG 纵切跑通。

**Q：引用准不准？**
> 当前是 section 范围引用，不是逐句精确页；公式缺失 73 篇有标记；下一步做逐句引用校验和人工抽查。

**Q：为什么拒答？**
> 证据不足时宁可拒答，也不把模型常识写成你的知识库事实。这是课程项目里“可信”的核心。
